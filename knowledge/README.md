# Knowledge

Facts, not procedure. A playbook says *what to do*; a `knowledge/` file says
*what's true* — about your tools, your footage, your process — so Claude
doesn't have to rediscover it every session.

## What goes here

- API/tool behavior you've verified in practice (a scripting quirk, a bug, a
  workaround) — see `resolve-api-gotchas.md` for a starter set
- A technique that works, with the numbers that show it (accuracy, timing,
  thresholds)
- Your own conventions once they stabilize (paths, naming, default settings)
  — start a `conventions.md` when you notice yourself repeating the same
  answer to "which settings do I use for X"

## How to write an entry

- Date it (`YYYY-MM-DD`)
- Say what was verified vs. what's still a guess
- Prefer a concrete example (a real clip, a real number) over a general claim
- When something you wrote here turns out to be wrong, correct it in place —
  don't leave stale facts for a future session to trip over
